# יועץ הרכב של שטראוס

בוט בעברית שעונה לעובד שזכאי לרכב חברה על השאלה "מה יקרה לנטו שלי?" אם יעבור לרכב אחר, לרכב חשמלי, או יוותר על הרכב. פרויקט להאקתון AI קוד פתוח 2026, אתגר שטראוס.

## עקרונות

- **החישוב בקוד, לא במודל השפה.** אותם נתונים ואותם כללים תמיד נותנים אותה תוצאה. המודל מנהל את השיחה ומפעיל כלים, וכל מספר בתשובה מגיע מפלט הכלי.

- **לא מנחשים.** כשחסר מידע, הבוט שואל את העובד או שולח שאלה לנציג התחבורה.

- **הכללים בקובץ הגדרות** (`backend/data/rules.json`): תקציבים, קבוצות, מסלול ברוכת ילדים, החזר חשמל, ויתור ושיטת הנטו. בפיילוט מחליפים נתונים ולא קוד.

## מבנה הפרויקט

```
vehicle-advisor/

│   │   ├── config.py       # טעינת rules.json, קטלוג הרכבים והעיסוקים מה-xlsx
│   │   ├── main.py         # FastAPI: נתיבי /chat, /compare, /agent ו-/health
│   │   ├── net_engine.py   # מנוע חישוב נטו: מס, ביטוח לאומי, גילום חשמל
│   │   ├── store.py        # SQLite: שמירת שיחות ושאלות לנציג
│   │   └── vehicles.py     # שליפת שווי שימוש מקובץ ה-CSV של רשות המסים

│   │   └── vehicle_value_2026.csv  # מאגר רשות המסים (לא כלול — ראה סעיף הפעלה)
│   ├── tests/              # 22 בדיקות: מנוע נטו, זכאות, ויתור, מסלול משפחתי, מסד נתונים

│   ├── pytest.ini
│   └── requirements.txt
```

## דרישות

Python 3.12, Node.js 20 ומעלה, ומפתח Gemini API (aistudio.google.com).

## הפעלה

### 1. נתונים

בתיקייה `backend/data` צריכים להיות שלושה קבצים:

- `challenge_data.xlsx` (קטלוג רכבים, עיסוקים ועובדים לדוגמה) ו-`rules.json`: כלולים בפרויקט.

- `vehicle_value_2026.csv` (מאגר שווי השימוש של רשות המסים, 77,988 רשומות, קידוד windows-1255): **לא כלול בפרויקט** בגלל גודלו. יש להוריד אותו מדף האתגר ולשמור בשם הזה בתיקייה. בלעדיו, שליפת שווי שימוש והבדיקות לא ירוצו.

### 2. Backend

```bat
cd backend
py -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
```

מעתיקים את `backend\.env.example` ל-`backend\.env` וממלאים את הערכים:

| משתנה | תיאור |
|---|---|
| `GEMINI_API_KEY` | מפתח API מ-aistudio.google.com |
| `GEMINI_MODEL` | שם המודל הראשי (ברירת מחדל: `gemini-3.8-flash`) |
| `GEMINI_MODELS` | רשימת מודלים מופרדת בפסיקים לגיבוי אוטומטי כשמכסה נגמרת או מודל לא זמין (לדוגמה: `gemini-3.8-flash,gemini-3.5-flash`) |

הרצה:
```bat
uvicorn app.main:app --reload
```

תיעוד ה-API: http://localhost:8000/docs

### 3. Frontend

```bat
cd frontend
npm install
npm start
```

פתיחה בכתובת http://localhost:4200. מסך עובד ב-`/` ומסך נציג ב-`/agent`.

### 4. בדיקות

```bat
cd backend
python -m pytest tests -q
```

22 בדיקות: משחזרות את נטו הייחוס של 6 העובדים לדוגמה בטווח עיגול של שקל, ובודקות זכאות, ויתור, מסלול משפחתי, מידע חסר ושמירת מצב.

## תרחיש הדגמה

1. **מסך עובד** — להדביק פרטי עובד (קבוצה, שכר, הפרשות, נקודות זיכוי, רכב נוכחי) ורכב יעד.

2. אם חסרה ההשתתפות ברכב החדש, הבוט אומר "חסר לי X, שאלתי את הנציג".

3. **מסך נציג** (`/agent`) — עונים על השאלה.

4. חוזרים למסך עובד וכותבים "קיבלת תשובה, תמשיכי". הבוט מחשב, ותצוגת ההשוואה מתעדכנת.

5. רענון הדף שומר את השיחה ואת ההשוואה.

## מה עובד

- שליפת שווי שימוש לפי המפתח הרשמי (שנת מס, שנת רישום, סוג רכב, קוד תוצר, קוד דגם), עם אימות מול 20 רכבי הקטלוג.

- זכאות: קבוצה נמוכה או שווה, מסלול ברוכת ילדים (4 ילדים ומעלה, פער 50/50), וויתור לפי עיסוק.

- החזר חשמל מגולם: העובד רואה בדיוק 250 ₪ נטו.

- מנוע נטו שמשחזר את 6 העובדים לדוגמה.

- שיחה ושאלות נציג שנשמרות ב-SQLite ושורדות רענון, והמשך שיחה אחרי תשובת נציג.

- תצוגת השוואה: רכב, זכאות, עלות מול תקציב, שווי שימוש, השתתפות, החזר חשמל או אחזקה, מס, ביטוח לאומי, נטו והפרש, והסבר קצר.

## מגבלות

- לוחות מס 2025 להמחשה בלבד, וחישוב חודשי (לא מצטבר). המספרים הם הערכה ולא תחליף לתלוש.

- פישוטים לפי קובץ הכללים: פנסיה וקרן השתלמות על כל הברוטו, והשתתפות ברכב אינה מקטינה את שווי השימוש.

- הרכב הנוכחי והרכב החדש נבחרים מקטלוג של 20 רכבים בלבד (לא מכל 77,988 הרשומות במאגר).

- הנתונים בהדגמה פיקטיביים, חוץ מקודי הרכבים ושווי השימוש.

- הבוט תלוי ב-Gemini. בשכבה החינמית יש מכסה יומית קטנה, ושמות מודלים משתנים. אכיפת "לא לנחש" נעשית דרך הפרומפט והכלים (כל מספר מגיע מפלט כלי), ולא דרך בדיקה אוטומטית של תשובת המודל.

- אין הזדהות והרשאות: כל מי שניגש ל-`/agent` יכול לענות על שאלות של כל שיחה. נתוני השכר נשמרים ב-SQLite מקומי בלי הצפנה.

- לא נתמכת העלאת תלוש או חוזה (אופציונלי בהנחיות).

- הממשק נבדק ב-Windows ובדפדפן Chrome בלבד.

## מה נדרש לפיילוט

- חיבור לנתוני עובדים אמיתיים והזדהות (SSO), עם הגנת פרטיות על נתוני שכר ושמירה מוצפנת.

- החלפת `rules.json`, הקטלוג והעיסוקים בנתוני אמת. לא נדרש שינוי קוד.

- בחירת רכב מכל מאגר רשות המסים, ולא רק מ-20 רכבי הקטלוג.

- מנוע מס מלא (לוחות עדכניים, חישוב מצטבר, הטבות יישוב).

- מודל בתשלום עם מכסה מתאימה ובלי שימוש בנתוני העובדים לאימון.

- מסד נתונים מרכזי והתראות לנציג על שאלות חדשות.

- בדיקה אוטומטית שהמספרים שמופיעים בתשובת הבוט תואמים לפלט החישוב.
